# 兴化语记作为部署实例：兼容、迁移与回滚边界

用户确认长期方向是整合现有系统、按需小范围重构；兴化语记未来作为通用系统的一个实例。本轮没有操作线上迁移、备份、权限或用户数据。

## 能力没有被“轻量版”无声替换

| 既有能力 | 当前代码/配置 | 轻量Compose默认 | 兴化实例后续启用要求 |
| --- | --- | --- | --- |
| 词典、文章、词单、录音、用户、消息、积分、答题等既有Django业务 | 原模型、迁移与API继续保留；新增移动词条申请复用原审核接口 | 仍用原后端，不是另写简化API | 导入经授权内容，验证真实账号与历史接口 |
| 莆仙音系、亲属计算、地区、日常用语、测验、曲库 | 源码、原语言资料及署名保留 | 泛方言示例关闭 | `config/examples/hinghwa.json`开启相应开关；真实词典/曲库/题库须由运营者导入 |
| 莆仙示例读音 | 原端点移至兴化实例配置的`phonologyAudioBase` | 空端点，禁止请求 | 确认原媒体使用授权/可用性；可改成自有端点 |
| 语义检索、FAISS、BGE及索引worker | 原实现、模型固定版本、完整依赖与管理命令保留 | **未安装ML依赖；显式关闭并使用既有关键词检索回退** | 另行构建/核验上游CPU完整依赖与固定离线模型，启用配置并启动原worker；本轮未验证完整ML镜像，不可称为功能全等的迁移包 |
| 录音/文件存储 | 既有COS适配保留，新增独立本地存储 | 本项目卷内存储，不调用原COS写入 | COS使用自己的环境凭据及`COS_PUBLIC_BASE_URL`；本地与COS的链接/删除行为需回放验证 |
| 邮件、微信登录、识别服务 | 原服务代码保留；私有输入不入公开JSON | 邮件输出控制台，微信入口关闭，识别功能关闭 | 用自己的SMTP/AppID/密钥/服务域名配置并单独验收；原站私有配置未复制 |
| 普通话麦克风识别Web演示 | 候选4移除许可未解决的讯飞demo派生实现及worker，不是仅隐藏按钮；原仓和Git历史保留 | 不提供语音识别；兼容旧路由的独立文字查词/可选拼音合成 | 需另行取得实现/服务许可并设计安全鉴权后再适配；配置开关不能恢复已移除实现或授予许可 |
| 积分插画、证书底图与二维码 | 候选4移除三份仅有项目使用授权的购买素材；新绘几何积分SVG和中性学习记录Canvas | 积分数据继续显示；证书数据仍走原API，可下载/打印中性学习记录；原证书外观/二维码不提供 | 兴化实例若确有使用权应在自己的独立部署素材层保管并单独验收，不能据历史购买推断通用模板再分发许可 |
| 原内部定时任务 | 原scheduler保留，可显式`ENABLE_BACKGROUND_SCHEDULER`启用 | 关闭，避免新实例自启动任务 | 核验任务唯一性、每日词及音频清理目录；本轮未启用第二套调度 |
| 原反馈渠道 | 公共ID/URL仅存在兴化实例配置 | 泛方言实例不打开原站反馈账号 | 可配置原渠道或自己的渠道；不沿用原站微信主AppID |

默认关闭只是独立空库演示的部署选择，不是删除相应能力，也不是宣称它们已适配另一种方言。语义检索等可选重依赖的部署验收仍是明确待办。

## 数据、媒体与路由

- 未改现有核心表/字段名。新增头像默认值迁移只改变新记录默认行为；既有头像URL不批量替换。原迁移文件、用户/词条/文章/录音ID、审核流继续保留。
- 原数据库不在包内。新实例创建独立`dictionary.sqlite3`。不得将本轮`migrate`直接指向生产数据库；应先在另一个隔离卷用经授权备份演练，并回放关键记录、权限、审核、通知和检索。
- 既有媒体URL按原值读取，不把COS对象无声改成本地路径。采用本地存储时应核验原`media`、`material/audio`及实际生成目录映射到新`MEDIA_ROOT`/`SAVED_PINYIN`的清单和校验和；本轮没有复制这些数据。
- Django原API路由继续由`HinghwaDict.urls`包含；同域示例通过`/api/`反向代理。旧API域名迁移时需保留同样路径及请求头/Token/CORS/CSRF约定，不能强迫现有客户端同时更新。
- Web原路由保留；通用实例按开关阻止原方言工具，兴化实例相应开启。H5候选挂载在`/mobile/`；提供旧`/pages/*`到`/mobile/pages/*`的302兼容转跳。原`m.hinghwa.cn`根路径/小程序深链仍需专项验收，不能称为已经无缝切换。

## 后续迁移与回滚顺序（仅说明，不执行）

1. 核验实际线上镜像/提交、数据库schema、在用配置及依赖；本轮三个上游提交不等于实际线上版本。本机后端两处未提交改动也未强行合入，迁移前单独审阅。
2. 取得明确的迁移窗口与数据操作授权后，制作可恢复数据库/媒体备份并验证恢复；记录原镜像、配置和路由。用隔离副本做迁移前后记录/计数/媒体校验与关键用户流程回放。
3. 审核兴化实例配置、原专属能力和可选重依赖差异，确认邮件/微信/后台任务不重复运行，完成Web/H5及小程序真机验收。
4. 再由用户授权具体切换。回滚保留旧镜像/配置/路由；有schema或写入差异时先恢复经验证的备份并处理切换后新数据，不能仅回退代码声称恢复完成。当前版本未提供生产自动回滚承诺。

未执行任何上述线上步骤。新实例测试数据与原站数据始终分开；停止演示容器保留卷。
