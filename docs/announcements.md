# 在网页后台管理公告

这是候选功能，已完成相关后端回归及部分合成数据浏览器验收；不要把本文当作线上已经更新的说明。完整范围见[验收记录](development/admin-validation-20261106.md)。

1. 使用自己已有的运营账号进入网站的 `/api/admin/`，打开“网页内容”，默认进入实际生效的首页配置；“查看所有配置”保留历史记录。若没有访问权限，请联系站点管理员；不要修改安全设置来进入。
2. 在“公告管理”输入标题关键词，点击“搜索文章”。每张结果卡显示标题、是否公开和发布日期；“文字预览”只显示文字，不执行文章中的HTML或脚本。
3. 点击“加入公告”，在“已选公告”用“上移”“下移”调整顺序，或“移除”。这里的顺序就是网站的新请求读取顺序；重复加入不会多出一条。
4. 加入“未公开”的文章不会让它通过审核，也不会在网站公开显示。只有本来具备文章查看权限的人才可搜索或预览未公开内容；已有选择中的无权查看项只显示编号占位，不泄露标题或正文。
5. 点击Django页面底部的“保存”。重新打开配置核对顺序，再打开网站确认效果；设计上保存后新请求直接读数据库，无需重启服务。本轮浏览器已核实排序保存后重开保持一致。

不想保存时点击“取消并返回（不保存）”；“恢复打开时的选择”只恢复当前页面最初打开的列表，之后仍需自己选择是否保存。搜索、预览、加入和上下移动本身都不保存。

原来的合法文章编号列表仍兼容，不需要手工重填或重新编号。本候选增加修复备份字段，上线此版本前仍须按安装指南执行数据库迁移；本轮已在合成数据临时数据库执行该迁移，尚未对生产或既有真实数据库迁移。旧配置若格式不正确，会提示错误并保留原值，不会自动清空；请先备份，再由管理员核对，不要反复保存来掩盖问题。

本轮只改善公告。站名、方言和端点目前仍按[安装指南](install.md)配置；密钥、数据库连接、网络和安全设置保持独立，不加入普通运营后台。热门文章、每日一词和轮播仍保留旧格式，不能据此声称所有运营配置已经网页化。

## 损坏配置的候选恢复流程

遇到格式错误时，搜索和排序先禁用，原值不变。查看只读原值，明确勾选“重新选择”后再选文章并保存；保存修复时保留一份完整原值。取消勾选、恢复打开时选择或取消返回都不会保存。

刚修复后可用“撤销上次修复并恢复原值”撤销；如果公告已再次被修改，会拒绝覆盖并保留备份。撤销会恢复原来的格式错误状态，便于重新核对；其他首页字段和文章公开状态不变。该功能新增一个只读修复备份字段和迁移，临时数据库迁移及对应自动回归已通过；损坏配置修复/撤销的完整浏览器验收尚未完成。

从“网页内容”默认进入当前实际生效首页；“查看所有配置”仍保留历史行。没有生效首页时，由已有新增权限的运营者明确点击创建，读取页面不会自动写入或覆盖旧行。上下移动后设计上保留操作焦点，按钮辅助名称包含标题；已核实默认进入生效首页；键盘焦点和修复流程仍需浏览器逐项验证。
